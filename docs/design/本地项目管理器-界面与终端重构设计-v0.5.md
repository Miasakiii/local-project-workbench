# 本地项目工作台

界面与终端重构设计讨论稿 · v0.5

日期：2026-10-25　状态：P0/P1 已完成，P2 待实施

> 本稿规划下一阶段的设计与实施顺序；P0/P1 已有验证证据，其余阶段仍须逐项实施后验收。
> 安全修复、依赖升级、结构重构、视觉重构和发布验收不得混成一个不可审查的大提交。

## 1. 设计目标与范围

### 1.1 目标

1. 收拢当前工作区变更、依赖审计和发布证据，使后续改造有可复现基线。
2. 在不改变既有行为的前提下拆分前端结构，降低 `App.tsx`、`ProjectPage.tsx` 和终端视图的耦合。
3. 保留 macOS / Finder 的中性视觉方向，重新组织项目工作区、设置页和终端工作区。
4. 以终端为重点改善可读性、会话状态、键盘交互、搜索和设置持久化。
5. 每阶段都有可执行验收门；最终发布验收覆盖真实 ACL、硬件 GPU、安装卸载与签名。

### 1.2 非目标

以下内容不进入本轮实施范围：

- 不迁移到 Tauri、Rust、GPUI 或 alacritty 引擎，继续使用 Electron、React、TypeScript 与 xterm。
- 不增加 Git stage、discard、commit、push、pull 等写操作，继续遵守 C06 的只读 Git 边界。
- 不做终端分屏、会话恢复、插件系统、主题市场、自动更新或崩溃上报。
- 不通过放宽 CSP、开放任意绝对路径或绕过主进程信任检查来换取界面便利。
- 不引入 Redux、MobX 或新的 UI 组件框架；先用现有 React 状态和纯函数模块完成解耦。

## 4. 前端结构设计

### 4.1 建议组件边界

```text
App
└─ AppShell
   ├─ ProjectSidebar
   ├─ LibraryPage / SettingsPage
   └─ ProjectWorkspace
      ├─ ProjectHeader
      ├─ ProjectContent
      └─ TerminalPanel
         ├─ TerminalTabs
         ├─ TerminalStatusBar
         └─ TerminalSessionView
```

约束：

- 不把所有状态继续上移到 `App.tsx`；优先使用局部状态和 hook。
- 不把 IPC 来源校验、项目信任、路径解析或 PTY 权限判断移入 React 组件。
- 不为了一次 UI 改造同时替换全部页面组件。
- 终端标签使用稳定标识；会话 ID 变化不等于标签身份变化。

### 4.2 视觉方向

保留当前冷灰、系统蓝、细分隔线和低饱和状态色。终端使用深色表面，不额外引入全局暗色主题改造。

建议布局：

```text
┌──────────────┬──────────────────────────────────────────┐
│ 项目库        │ 项目名 / 路径        概览 文件 变更       │
│ 项目 A        │──────────────────────────────────────────│
│ 项目 B        │                                          │
│ 项目 C        │             内容工作区                    │
│              │                                          │
│──────────────│──────────────────────────────────────────│
│ 设置          │ 终端标签 + 状态       搜索 新建 结束 展开 │
│              │ 终端输出 / 回滚 / 状态栏                  │
└──────────────┴──────────────────────────────────────────┘
```

- 项目头部减少徽章和操作混排，操作按钮按主操作、次操作和危险操作分层。
- 侧栏只承担项目切换和设置入口，不复制页面导航。
- 终端展开后获得稳定空间；收起时不卸载终端视图。
- 动效只表达状态，不为装饰增加持续动画；提供减少动态效果的兼容策略。

## 5. 终端设计

### 5.1 会话与状态

终端区域需要明确展示：

- 当前 Shell。
- 项目内启动目录。
- 会话状态：启动中、运行中、已退出、启动失败。
- 当前标签和隐藏会话的活动状态。

关闭运行中会话仍需确认；不能因为换成图标按钮或新布局而省略确认。

### 5.2 快捷键

建议快捷键：

| 操作 | 建议快捷键 |
|---|---|
| 展开 / 收起终端 | Ctrl+` |
| 新建会话 | Ctrl+Shift+T |
| 切换会话 | Ctrl+Tab / Ctrl+Shift+Tab |
| 关闭会话 | Ctrl+Shift+W |
| 搜索回滚 | Ctrl+Shift+F |
| 放大 / 缩小 / 重置字号 | Ctrl+= / Ctrl+- / Ctrl+0 |

实施前需检查与现有快捷键和 Windows 终端输入的冲突，并在设置页展示实际生效的快捷键。

### 5.3 搜索与链接

- 搜索优先采用 xterm 官方 search addon，并增加对应依赖审计。
- 搜索结果需要当前匹配、总数和上下移动能力。
- 链接打开仍需经过明确协议校验和主进程边界，不允许渲染层任意拉起外部程序。
- 不把搜索、链接或状态展示变成采集命令内容的后门。

### 5.4 终端设置

设置页至少覆盖：

- 默认 Shell。
- 默认启动目录：项目根目录或当前目录。
- 字体、字号、行距、字间距。
- 光标样式和闪烁。
- 最小对比度。
- 滚动回滚行数。
- 复制即选。
- 链接打开行为。
- 快捷键说明。

设置数据要求：

- 使用现有应用设置存储和原子写入机制。
- 缺省值、范围校验、损坏回退必须有测试。
- 打开中的终端可安全应用外观设置；需要重建会话的设置不得静默重建。
- 不把新的设置持久化继续散落在难以审计的 localStorage 键中。

## 7. 提交与回滚策略

建议提交边界：

1. `test`：先补基线和回归验证。
2. `chore` / `ci`：依赖与发布链路收口。
3. `refactor`：前端无行为变化解耦。
4. `feat`：终端设置与交互改造。
5. `docs`：设计稿、验证口径和发布记录同步。

每个提交都必须能独立构建和验证。不得用 `reset --hard`、强制覆盖或批量删除来回滚；回滚以已审查提交和明确备份为基础。

## 8. 待评审决策

实施前需要确认以下默认值：

- UI 继续采用 macOS / Finder 中性外壳，终端采用深色工作区。
- 终端以底部可收起面板加聚焦模式为主，不改为三栏终端专用布局。
- 第一轮终端增强不包含分屏、会话恢复、Git 写操作和自动更新。
- 终端设置统一持久化到应用设置存储，并逐步替代现有分散存储。
- 搜索功能允许增加 xterm 官方 addon，但必须先做依赖审计。

上述决策确认后，按 P0 → P1 → P2 → P3 → P4 → P5 顺序实施；任何阶段未通过完成门，不进入下一阶段。
