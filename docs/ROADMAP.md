# 路线图

本文件登记本地项目工作台的剩余待办，按 P0／P1／P2 优先级编排：P0 是公开分发前的硬阻断与决策项，P1 是决策通过后的接入项，P2 是已登记限制的跟进与远期项。

**维护约定：**

- 与 [README](../README.md)「项目状态」和 [CHANGELOG](../CHANGELOG.md) 保持同步：完成一项，更新该项「状态」；实际变更登记进 CHANGELOG「未发布」区段，README「已知限制」口径随项收口。
- 每条待办必须有来源依据（括注文件与行号），新增条目须明确标注「本次分析新增」。
- 标注「需要用户决策」的条目在决策落档前不实施；标注「需要外部资源」的条目受证书等外部条件约束。
- 状态取值：未开始／进行中／已完成／维持登记（含「条件触发」与「不投入」两种）。

## P0 — 公开分发前的硬阻断与决策项

### P0-1 配置代码签名证书（CSC_LINK／CSC_KEY_PASSWORD）并复验签名分发

- **状态**：未开始（需要用户决策与外部资源）
- **目标**：新发布 Release 的安装包、主程序与 `elevate.exe` 数字签名有效（非 `NotSigned`），SmartScreen 不再提示未知发布者。未签名状态是公开分发唯一硬阻断。
- **验收标准**：三项产物签名均有效；签名后安装／卸载与打包产物验证 12/12 复验通过。
- **依赖或前置**：需要外部资源——代码签名证书（类型与费用待定）。发布链已预留接缝：`.github/workflows/release.yml` 经 `CSC_LINK` / `CSC_KEY_PASSWORD` 仓库 secrets 启用签名，未配置时产物未签名。
- **预估规模**：medium
- **是否需要用户决策**：**需要**（证书采购与费用属外部资源决策）。
- **来源**：README.md:202（已知限制「公开分发前需配置代码签名证书」）；README.md:397（0.3.0 三项产物 `NotSigned` 与哈希）；CHANGELOG.md:82；CHANGELOG.md:138。

### P0-2 公开分发前完成分发策略三项产品决策：i18n／自动更新／崩溃上报

- **状态**：未开始（需要用户决策）
- **目标**：i18n、自动更新、崩溃上报三项均有书面决策（接入或明确暂不），并回写 README「已知限制」与 CHANGELOG 口径。决策本身是公开分发前必须完成的事项。
- **验收标准**：三项决策落档；README.md:203 的「需另行决策」表述按结论更新，不冒充已支持。
- **依赖或前置**：是 P1-1／P1-2／P1-3 的前置——三项是否实施取决于本决策结论。

## P1 — 决策通过后的接入项

### P1-1 接入自动更新（electron-updater + GitHub provider）

- **状态**：未开始（待 P0-2 决策）
- **目标**：electron-updater 以 GitHub provider 接入，`latest.yml` / `app-update.yml` 指向真实 ASCII 产物名。
- **验收标准**：在真实旧版本上完成一次「检测 → 下载 → 升级」端到端验证。
- **依赖或前置**：P0-2 决策结论为「接入」。当前显式 `publish: null`，不生成更新元数据；接入时改 GitHub provider 并保持 ASCII `artifactName`——中文产物名会破坏更新元数据（0.1.0 曾产生指向不存在文件的 `latest.yml`）。
- **预估规模**：medium
- **是否需要用户决策**：**需要**（是否接入由 P0-2 决定）。
- **来源**：CHANGELOG.md:50；electron-builder.yml:20-24；CHANGELOG.md:64（ASCII 产物名缘由）。

### P1-2 接入 i18n 国际化

- **状态**：未开始（待 P0-2 决策）
- **目标**：界面文案经 i18n 资源加载，目标语言可切换且无硬编码中文残留。
- **验收标准**：文案相关断言与 `capture:ui` 视觉基线同步更新。
- **依赖或前置**：P0-2 决策确定语言范围。当前界面仅简体中文，语言包裁剪只保留 zh-CN / en-US；文案散布在渲染层各组件，抽取与资源化工作量大。
- **预估规模**：large
- **是否需要用户决策**：**需要**（语言范围由 P0-2 确定）。
- **来源**：README.md:203；README.md:351。

### P1-3 接入崩溃上报

- **状态**：未开始（待 P0-2 决策）
- **目标**：崩溃可被采集并上报（或按决策仅本地落盘），补齐公开分发后的诊断通道——当前崩溃只能靠用户手动反馈。
- **验收标准**：上报内容不含用户路径等敏感信息；用户可关闭，关闭后无网络外发。
- **依赖或前置**：P0-2 决策确定接入与隐私口径。接入网络上报须重新审视「唯一对外请求出口」边界（当前仅 `modules/remote-image.ts` 访问网络）——上报通道要么并入该出口治理，要么作为第二个显式收口的外呼通道，并同步修订 README「安全边界」。
- **预估规模**：medium
- **是否需要用户决策**：**需要**（接入与隐私口径由 P0-2 决定）。
- **来源**：README.md:203；README.md:125。

## P2 — 已登记限制的跟进与远期项

### P2-1 dxcompiler.dll／dxil.dll 与 SwiftShader 约 32 MB 的裁剪前逐项静态核查

- **状态**：维持登记（条件触发——仅当未来重启裁剪评估时执行；当前维持保留决策）
- **目标**：产出逐 DLL（dxcompiler／dxil／vk_swiftshader／vulkan-1）加载清单静态核查记录，并据此更新 `electron-builder.yml` 与 README 的裁剪／保留表。
- **验收标准**：核查记录落档，裁剪／保留表与记录一致。
- **依赖或前置**：既有核查均通过仍不构成裁剪依据——「两条路径均正常仍不足以证明二者永不被加载」，故当前保留。
- **预估规模**：small
- **是否需要用户决策**：不需要（当前决策为保留；是否重启裁剪评估届时再议）。
- **来源**：README.md:200；README.md:373；electron-builder.yml:5-8。

### P2-2 WebGL 不可用时 DOM 渲染降级的改善

- **状态**：未开始
- **目标**：无 WebGL 环境下终端保留 ANSI 颜色与搜索高亮（或向用户明示降级状态）。
- **验收标准**：生产态 CSP 不放宽；终端全套验证与打包产物双路径验证通过。
- **依赖或前置**：WebGL 渲染器（2026-10-25 引入）只是现行方案；降级路径的视觉品质是已登记限制——生产态 CSP 禁止内联样式，DOM 渲染器丢失颜色与高亮，输入输出不受影响。
- **预估规模**：medium
- **是否需要用户决策**：不需要。
- **来源**：README.md:201；CHANGELOG.md:110；docs/design/本地项目管理器-界面与终端重构设计-v0.5.md:156。

### P2-3 TOCTOU 残余微秒级窗口——维持已接受登记，不重复投入

- **状态**：维持登记（不投入）
- **目标**：不投入工程手段；维持 README／CHANGELOG 的风险表述与 `verify:m3-file-ops` 竞态注入、守卫开销实测口径一致，无未登记的缓解缺口。
- **验收标准**：口径一致，无未登记缺口。
- **依赖或前置**：多重收窄已落地（拒绝重解析点写目标、物理身份快照、执行前后复核、守卫开销实测中位约 11 µs）；剩余窗口没有对策——路径 API 无法归零，如需更强保证应改用原生句柄级／无替换操作（见 P2-4）。
- **预估规模**：small
- **是否需要用户决策**：不需要。
- **来源**：README.md:199；docs/design/本地项目管理器-界面与终端重构设计-v0.5.md:91。

### P2-4 R9 原生句柄级写守卫（N-API addon，可选独立工程）

- **状态**：维持登记（需要用户决策是否立项）
- **目标**：以 N-API addon 提供句柄级／无替换写操作，进一步收窄 TOCTOU 残余窗口（见 P2-3）。
- **验收标准**：原生守卫默认关闭时行为与现状一致（`verify:r9-native-guard` 全绿）；开启后写路径竞态注入套件全绿，并有守卫开销实测记录。
- **依赖或前置**：需要 Windows C++ 工具链与独立 E2E 竞态验证；原生构建链与回收站语义的冲突是主要代价——Windows 无「无替换」原生写（`fs.rename` 走 `MoveFileEx` + `REPLACE_EXISTING`，已废弃的 TxF 不作备选），A2 决策门因此默认关闭。回退契约（`loadNativePathGuard() → null`）已有 4 项断言覆盖，集成接缝（`resolveForWrite` / `writtenTargetIntact`）已保留。
- **预估规模**：large
- **是否需要用户决策**：**需要**（是否投入由用户决定）。
- **来源**：README.md:199（TOCTOU 残余窗口 R9 登记）；README.md:298（`verify:r9-native-guard` 回退契约验证行）。

### P2-5 终端远期增强：分屏与会话恢复

- **状态**：维持登记（需要用户决策是否立项）

- **验收标准**：若立项——不违反「不自动启动或恢复进程、不隐式执行命令」边界，`smoke:m1` 与全部终端套件回归通过。
